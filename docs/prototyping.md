# Как устроен прототип

## Маршруты и состояние

| Маршрут        | Назначение                                               |
| -------------- | -------------------------------------------------------- |
| `/`            | Главная, поиск и рекомендации                            |
| `/search`      | Выдача, фильтры и сортировка                             |
| `/listing/:id` | Галерея, характеристики и локальная форма связи          |
| `/auction`     | Учебный аукцион квартиры: сценарии продавца и покупателя |
| `/ui`          | Каталог общего UI-kit                                    |
| `/patterns`    | Компоненты страниц и ссылки на состояния                 |
| `/guide`       | Краткое руководство дизайнера                            |

`src/data/listings.ts` содержит тип `Listing`, восемь синтетических объявлений и чистую функцию фильтрации. Поиск — подстрока по названию, адресу, району и метро, а не семантический AI-поиск. Цены и площади демонстрационные. Фотографии взяты как визуальные референсы и не описывают синтетические объявления; кадры одной демонстрационной галереи могут относиться к разным объектам.

Параметры `q`, `rooms`, `maxPrice`, `sort`, `favorites=1` хранятся в URL. Пустая комнатность означает любую, `0` — студию. Сортировка: `default`, `price-asc`, `price-desc`, `area-desc`. Кнопка возврата из карточки сохраняет URL выдачи; прямой вход в карточку возвращает к общему поиску.

`PrototypeProvider` хранит избранное в `localStorage` (`cian3:favorites:v1`), предоставляет `showDemo(title)` для незапроектированных разделов и `notify(text)` для статуса действий. Недоступный или повреждённый storage не мешает работе приложения. Реальной отправки сообщений, авторизации, аналитики или запросов к API Циана нет.

## Композиции

| Компонент        | Использование                                                                 |
| ---------------- | ----------------------------------------------------------------------------- |
| `AppShell`       | Header + содержимое + Footer; один раз на продуктовую страницу                |
| `PageLayout`     | Контейнер с `children` и необязательным `aside`; на телефоне одна колонка     |
| `Breadcrumbs`    | `items: {label,to?}[]`                                                        |
| `ListingCard`    | `listing: Listing`, `compact?: boolean`; общее избранное и переход в карточку |
| `SearchBar`      | Поиск с главной                                                               |
| `SearchFilters`  | `params: URLSearchParams`, `onApply(next)`                                    |
| `Sorting`        | `value`, `onChange(value)`                                                    |
| `Gallery`        | `images`, `title`; выбор кадра и диалог просмотра                             |
| `ListingActions` | `listing`; цена, продавец и локальная форма                                   |
| `PrototypePage`  | Шаблон нового сценария с `title`, `description?`, `children`, `aside?`        |

## Проверка состояний

- `/search?state=loading` — постоянный skeleton для ревью.
- `/search?state=empty` — пустая выдача.
- `/search?q=Сокольники&state=error` — ошибка; повторная попытка сохраняет фильтры.
- `/search?q=НесуществующийРайон` — естественная пустая выдача.
- `/search?favorites=1` — пустое или заполненное избранное.
- `/listing/unknown` — неизвестное объявление.
- `/auction` — продавец: условия → проверка → публикация. После публикации кнопка открывает карточку покупателя.
- `/auction?role=buyer` — карточка покупателя с горизонтальной фотогалереей и подача ставки; сумма ниже 18 900 000 ₽ показывает валидацию, корректная ставка — локальное ожидание и успешный статус.
- `/auction?role=buyer&state=error` и `/auction?role=buyer&state=finished` — ошибка ответа и завершённый аукцион.

Обычная выдача использует небольшую демонстрационную задержку 280 мс. Маршрут `/patterns` даёт доступ ко всем состояниям без редактирования кода.

## Границы готовности

Это основа для новых кликабельных сценариев. Карта, ипотека, личный кабинет, размещение объявления, сравнение и серверная отправка не реализованы. Они дают локальный демонстрационный ответ. Задание участников (например, размещение или новый тип объявления) не решено заранее. Базовое приложение светлое; тёмный режим проверяется в каталоге UI-kit.
